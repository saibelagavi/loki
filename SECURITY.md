# Security

LOKI stores secrets, so its security model is written down here in full. If anything below is
wrong or incomplete, please report it.

## Reporting a vulnerability

Please do **not** open a public issue for a security problem.

- Use GitHub's **Report a vulnerability** button on the repository's Security tab (private
  vulnerability reporting), or
- email **belagavisainath1@gmail.com** with "LOKI security" in the subject.

Include the version, what you found and how to reproduce it. You will get a reply within 7 days.
Please give a reasonable time to ship a fix before disclosing publicly. Never include real secrets
in a report; use fake values.

## Supported versions

Only the latest release gets security fixes.

## Design

### Offline by construction

- No networking code in the production build. `npm run check:offline` fails the build if the
  Windows production dependency graph contains an HTTP, TLS or WebSocket client, if `tokio` has
  network features, if the frontend uses `fetch`, `XMLHttpRequest`, `WebSocket` or
  `EventSource`, or if an `http(s)://` URL appears in the frontend source.
- Content Security Policy:
  `default-src 'self'; img-src 'self' data:; style-src 'self' 'unsafe-inline'; connect-src ipc: http://ipc.localhost`.
- No updater, no telemetry, no crash reporter, no web fonts from the network (the one font, Exo 2,
  is bundled).

### Keys

- The master password is never stored. Argon2id (m = 64 MiB, t = 3, p = 1, random 16-byte salt)
  derives 64 bytes: `enc_key` (32 B) for XChaCha20-Poly1305 and `fp_key` (32 B) for HMAC-SHA256.
- The vault stores the salt, the KDF parameters and a verifier (a fixed constant encrypted with
  `enc_key`). A wrong password is rejected with a generic message after a 1-second delay.
- Keys live only in process memory, in a type that is zeroized on drop. Locking (manual, idle
  timeout, or optionally on minimize) drops them.
- Changing the master password re-encrypts every value, comment and password in one database
  transaction.

### Values at rest

- Every value: a fresh random 24-byte nonce, associated data `"{snapshot_id}:{key}"`, so a
  ciphertext cannot be moved to another row or key.
- Comments are encrypted the same way (they often contain values).
- Passwords: two blobs per entry (list fields; password and notes), each bound to a random 16-byte
  row id.
- Key names, project names, branch and stage names are stored in plaintext, so search and diff
  are fast. Treat them as visible to anyone who can read the database file.
- Fingerprints (HMAC-SHA256 with `fp_key`) let LOKI tell whether two values are equal without
  decrypting them. They differ between vaults.

### Values in use

- The interface receives key names, statuses, counts and 8-character fingerprints. A value reaches
  it only on an explicit Reveal (hidden again after 10 s by default) or in the Diff checker when you
  ask to see values (hidden after 60 s by default).
- Every reveal, copy, export, share, import, delete and password change is written to a local
  audit log that records which key, never the value.
- Copy happens in the Rust core. The clipboard entry is excluded from Windows clipboard history
  and cloud clipboard, and cleared after 30 s if it still holds LOKI's value.
- Save dialogs for exports, shares and backups are opened by the core, so the interface never
  chooses where a file is written.
- No Rust code in LOKI prints or logs; a test fails the build if a print or log macro appears.

### Files LOKI writes

- `%LOCALAPPDATA%\LOKI\loki.db`: the vault (SQLite).
- `%LOCALAPPDATA%\LOKI\backups\`: a full copy written automatically before a schema upgrade.
  These copies are encrypted the same way as the vault.
- `%LOCALAPPDATA%\LOKI\webview\`: the WebView2 profile (theme preference, cache).
- Exports, backups and shares go only where you choose in a save dialog.

### Backups and shares

- `.loki` backups and `.lokishare` files: Argon2id + XChaCha20-Poly1305 under their own password
  or pass key, with the file header (magic, KDF parameters, salt) authenticated as associated data.
  A crafted header asking for absurd KDF memory is rejected before any work is done.
- Share pass keys are generated by LOKI: 25 Crockford base32 characters (125 bits). A typed pass
  key is refused, so a share can never be protected by a guessable one. The key is shown in the
  share window (so it can be copied before the file is written) and dropped when the window
  closes; it is never stored. Send the file and the pass key through different channels.
- A share holds one or more `.env` files with their project, branch and stage names, all inside
  the encrypted payload. On import, values stay in the Rust core; the interface sees key names.
  Every destination is checked before anything is written, and each import adds a new version
  (nothing is overwritten).

## Limits (what LOKI does not protect against)

- **Malware on your computer.** A keylogger can capture the master password; code running as you
  can read process memory while the vault is unlocked.
- **Revealed values.** Once shown on screen, a value is also in the WebView's memory until the
  page drops it. The "hide from screen capture" setting helps against screen sharing and
  screenshot tools, not against a camera or malware.
- **Plaintext files you export.** A full `.env` export is plaintext by design. Delete it when done.
- **Share expiry** is enforced by LOKI on import, not by the cryptography: someone who has both
  the file and the pass key can decrypt it with their own tools after the expiry date.
- **Weak master passwords.** Argon2id slows guessing, it does not make a weak password strong.
- **Key names and project names** are not encrypted (see above).
- **Unsigned builds.** Until releases are code-signed, verify you downloaded from this
  repository's Releases page or the Microsoft Store.

## Cryptography libraries

RustCrypto `argon2`, `chacha20poly1305`, `hmac`, `sha2`; `zeroize`; randomness from the OS CSPRNG
(`rand::rngs::OsRng`). LOKI does not implement any cryptographic primitive itself.
